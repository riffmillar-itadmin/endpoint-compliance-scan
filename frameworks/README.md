# Framework catalogs

Each `.psd1` file here is one framework the scanner can evaluate. The scanner
loads every file in this folder, so adding a framework means adding a catalog;
the script itself doesn't change unless a requirement needs a new named check.

The NIST and DISA STIG catalogs are generated by `tools/Update-FrameworkCatalog.ps1`
from the sources pinned in `tools/mappings/sources.psd1`, with the check mappings
in `tools/mappings/`. Change a mapping there and regenerate, rather than editing
these files. A STIG catalog follows the DISA release pinned for it where there is
one (Windows 11, Server 2022 and 2025, and the Firewall), and PowerStig's release
otherwise. Where PowerStig's automation keeps one of several allowed values, or
misses a waiver, a correction in `tools/mappings/disa-stig.psd1` gives the STIG's
values, with the reason.

PowerStig doesn't process the Active Directory Domain and Forest STIGs, so their
catalogs come from DISA's zip alone: DISA's rules and severities, with the
automated rules listed under `Automated` in `tools/mappings/disa-stig.psd1`.
Those were checked against the release named in `Release`, and the generator
stops on any other release until a person checks them again. Every other rule
is Manual.

NIST publications and the HIPAA regulation are US government works. The CIS
Controls and PCI DSS are copyrighted by their publishers, so their catalogs carry
only requirement numbers and titles written for this project, never the
standards' text. Get the standards from their publishers for the authoritative
wording.

## Format

```powershell
@{
    Id             = 'CMMC'                  # what -Framework takes (the file name works too)
    Name           = 'CMMC Level 1/2 (...)'  # shown in the summary and the JSON report
    Source         = 'https://...'           # where the framework is published
    Levels         = @('L1', 'L2')           # in order; a level includes the ones before it
    Complete       = $true                   # $false: the catalog is a subset, and reports say so
    PracticeFormat = '{Family}.{Level}-{Id}' # optional: how the Reference column is built (default '{Id}')
    StigId         = 'MS_Windows_..._STIG'   # optional: the STIG's benchmark ID, for STIG catalogs
    AppliesTo      = @{ ProductTypes = @(3); Builds = @(20348) }  # optional: the Windows it is written for
    Thresholds     = @{ MinPasswordLength = 14 }  # optional: overrides ComplianceScan.example.psd1
    Requirements   = @(
        @{
            Id     = '3.1.8'                 # unique within the catalog
            Family = 'AC'                    # groups the summary table
            Level  = 'L2'                    # one of Levels
            Title  = 'Limit unsuccessful logon attempts'
            Checks = @('AC-AccountLockout')  # named checks in the script; all are evaluated
            Expect = @( ... )                # optional setting expectations, below
            Note   = '...'                   # for a requirement with no evidence: what to look at
                                             # instead; otherwise: what the evidence leaves out
        }
    )
}
```

`AppliesTo` names the Windows a catalog is written for. The scan warns, and the
report says so, when the machine is another. A catalog without it applies to
any Windows. Every key is optional:

| Key | Meaning |
| --- | --- |
| `ProductTypes` | `1` client Windows, `2` domain controller, `3` Windows Server that isn't a domain controller |
| `Builds` | OS build numbers, such as 17763 (Server 2019), 20348 (Server 2022) and 26100 (Server 2025) |
| `MinBuild` | The lowest build, such as 22000 for Windows 11 |

A requirement with neither `Checks` nor `Expect` is Manual and must have a
`Note`. Otherwise its state is the worst of its checks and expectations.

Catalogs are read as data in PowerShell's restricted language: literals, arrays
and hashtables only, no commands and no variables other than `$true`, `$false`
and `$null`. A catalog that tries anything else is refused.

### Expectations

Each expectation is one setting with a required value.

| Source | Fields | Reads |
| --- | --- | --- |
| `Registry` | `Path` (`HKLM:\...` or `HKCU:\...`), `Name`, an operator; optionally `FallbackPath` | The registry value. Unset fails, unless `AbsentOk = $true`. With `FallbackPath`, a value unset under `Path` (the Group Policy key) is read under `FallbackPath` (the local setting) instead. `HKCU` is the scanning user's hive. |
| `SecPol` | `Name` (a `[System Access]` key from `secedit /export`, or a `[Kerberos Policy]` key, which Windows exports only on a domain controller), an operator | The local security policy. Undefined fails. |
| `Audit` | `Subcategory` (English name), `Setting` (`Success`, `Failure` or `SuccessAndFailure`) | Advanced audit policy, matched by GUID, so any display language works |
| `UserRight` | `Name` (a right such as `SeNetworkLogonRight`), `Op` (`only` or `includes`), `Identities` | Who holds the right, from `secedit /export`. Needs elevation. Below. |
| `Service` | `Name`, `StartType` | The service's start type. A service that isn't installed passes. |
| `Feature` | `Name`, `State = 'Disabled'` | A Windows optional feature, or on Windows Server a role or feature (the `Get-WindowsFeature` name). Installed or enabled fails, including a change waiting on a restart; anything else passes, as does a feature this Windows doesn't offer. Needs elevation. |
| `Directory` | `Name` (a directory test, below) | Active Directory, read on a domain controller. NotApplicable on any other machine. |

Operators for `Registry` and `SecPol`:

| `Op` | Field | Passes when the value |
| --- | --- | --- |
| `eq` | `Value` | equals it (text comparison ignores case and spaces) |
| `ne` | `Value` | differs from it |
| `ge` | `Value` | is a number at least this large |
| `between` | `Min`, `Max` | is a number in this range, inclusive |
| `in` | `Values` | equals one of them |
| `notempty` | | is not blank |

`DomainOnly = $true` on any expectation makes it NotApplicable on a machine that
isn't joined to a domain, for STIG rules that say "for standalone or
nondomain-joined systems, this is NA". `StandaloneOnly = $true` is the opposite:
NotApplicable on a domain member.

`NotApplicableIf = @{ Rules = @(...); Expect = @(...) }` on an expectation makes
it NotApplicable when every expectation in `Expect` passes, for STIG rules that
say "if WN25-00-000380 is configured, this is not applicable". `Rules` names the
rules those expectations come from, for the evidence. The generator copies them
from the named rules, so they always match. If any of them doesn't pass, or can't
be judged, the expectation is judged as usual.

`Also = @(...)` lists extra values that pass, for example `Also = @(0, -1)` on a
lockout duration where 0 and -1 mean "until an administrator unlocks it".

### User rights

`Op = 'only'` passes when everyone holding the right is in `Identities`; an
empty `Identities` means no one may hold it. `Op = 'includes'` passes when each
of `Identities` holds it, whoever else does. An entry `'A|B'` is satisfied by
either.

Identities are matched by well-known SID where there is one (Administrators,
Users, Guests, Remote Desktop Users, Authenticated Users, Service, Local Service,
Network Service, Local account, Local account and member of Administrators group,
Enterprise Domain Controllers, NT Virtual Machine\Virtual Machines, Domain Admins,
Enterprise Admins), and otherwise by the full account name, such as
`RESTRICTED SERVICES\PrintSpoolerService`. Domain Admins and Enterprise Admins
are matched in any domain, and `includes` doesn't require them on a machine
outside a domain. A holder whose SID no longer resolves fails `only`.

### Directory tests

A `Directory` expectation names one test in the script. Each reads the directory
snapshot taken on a domain controller. Groups are found by well-known SID, so any
display language works, and nested membership counts. Only enabled accounts
count as members.

| `Name` | Fails when | Manual or NotApplicable when |
| --- | --- | --- |
| `EnterpriseAdminsSeparate` | an Enterprise Admins member is also in Domain Admins, Schema Admins, Backup Operators or Server Operators | Manual when members exist, to confirm each is a separate, documented account |
| `DomainAdminsSeparate` | a Domain Admins member is also in Enterprise Admins, Backup Operators or Server Operators | as above |
| `PrivilegedNotDelegated` | a member of a privileged group isn't marked sensitive and can be delegated | |
| `ProtectedUsers` | two or more administrative accounts of this domain are outside Protected Users (the STIG allows one) | NotApplicable below the 2012 R2 functional level |
| `UnconstrainedDelegation` | a computer other than a domain controller is trusted for unconstrained delegation | |
| `LapsCoverage` | | Manual when an enabled computer has no LAPS password, or the schema has no LAPS attributes |
| `SmartCardHashRolling` | the domain doesn't roll NTLM secrets of smart card accounts | Manual below the 2016 functional level |
| `DsrmPasswordAge` | the last DSRM password change (event 4794) is over a year before the scan | Manual when the Security log has no such event |
| `DomainFunctionalLevel` | the domain functional level is below Windows Server 2016 | |
| `TrustSidFiltering` | an outgoing external trust isn't quarantined, or a forest trust allows SID history | NotApplicable with no outgoing trust outside the forest |
| `SelectiveAuthentication` | an outgoing forest trust doesn't use selective authentication | NotApplicable with no outgoing forest trust |
| `PreWindows2000Access` | Pre-Windows 2000 Compatible Access includes Everyone or Anonymous Logon | |
| `TrustBuildersAndPolicyCreators` | | Manual when Incoming Forest Trust Builders or Group Policy Creator Owners has members |
| `InterSiteReplication` | a site link replicates less often than daily | NotApplicable with one site; Manual when a link has a schedule |
| `DomainControllerCount` | | Manual with one domain controller |
| `SchemaAdminsEmpty` | Schema Admins has members | NotApplicable outside the forest root domain |
| `AnonymousForestAccess` | the seventh character of `dSHeuristics` is 2 | |
| `ForestRootPdcTime` | the forest root PDC emulator's time type isn't NTP | NotApplicable on any other domain controller; Manual otherwise, to confirm the server |
| `CertificateTemplateApproval` | a published template without manager approval allows smart card logon, any purpose or no EKU, or client authentication with a subject supplied in the request | NotApplicable without an enterprise certificate authority |

The trust tests read the `trustAttributes` bits that MS-ADTS defines.

The test suite checks every catalog's shape, and checks that a snapshot meeting
every expectation in it passes, so a malformed catalog fails CI rather than a
scan.
